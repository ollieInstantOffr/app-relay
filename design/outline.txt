Relay — reverse proxy manager, UI mockups
Assumptions:
homelab self-hoster, light mode, icon rail + card grid, slide-over drawer for add/edit. "Relay" is a placeholder name. Clean/neutral direction: near-black accent, one signal green for health, amber/red only for warnings.
Round 2:
HAProxy load balancing lives under a new rail item "Load balancer" (backends → servers, algorithms, health checks, sticky sessions; haproxy.cfg is generated and hot-reloaded, never hand-edited). Login is username + password; a 3-step wizard creates the first admin. MCP server sits in Settings with tokens, tool permissions and an audit trail.
Round 3:
"Expose online" wizard (14) turns a backend into a public proxy host in 4 steps — Relay creates a localhost-only HAProxy frontend and an nginx host pointing at it, so the proxy stays the single public entry. All 9 settings pages are now drawn (08, 13, 15a–c, 16a–d).
Round 4:
config safety (17: versions, diff, rollback, pending-changes bar, auto-rollback toast) · host Locations + Advanced tabs (18: forward-auth, rate limit, body size, nginx snippet) · HAProxy Frontends & Stats (19) · Redirects + default host (20) · Audit log with MCP approvals inbox (21) · empty/error/offline states (22) · component sheet: toasts, dialogs, menus, ⌘K palette, tooltips, field states (23).
Round 5:
brand + icon set (24) applied to every rail · expose wizard steps 3–4 (25) · first-run wizard steps 2–3 (26) · hosts table view with bulk actions (27).
Round 6:
remaining drawers/dialogs (28–30): access list with basic-auth users, stream editor, add user, one-time token reveal, log detail with timing + block-IP, certificate detail (chain, SANs, history, used-by), Docker bulk suggestions, HAProxy frontend rule builder, shortcuts sheet, session-expired re-auth, viewer not-allowed, host SSL tab with per-host HTTP/3.
